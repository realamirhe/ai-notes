# Demystifying Agent Skills: Why They Work—Until They Don’t

## Findings

- Skills mainly act as **procedural anchors**. Use them to preserve reliable action sequences, tool usage, checks, and lessons from recurring failures.
- Skills do not appear to meaningfully add knowledge to a capable model. Keep general knowledge and project documentation outside skills unless they are required to execute the procedure.
- Large skill libraries make it harder for the agent harness to retrieve the right skill. Prefer a small set of skills with distinct purposes.
- Semantically similar skills create retrieval ambiguity. Merge skills with overlapping names, descriptions, triggers, or procedures.
- Retrieving the correct skill does not guarantee correct execution. The agent must still check whether the skill applies and adapt it to the current task.
- Rigid skills can introduce failures when their assumptions or boundaries do not match the project. State when a skill applies, when it does not, and what must be checked first.
- Skills are most useful for repeatable operational work such as setup, command sequences, service lifecycle, debugging routines, and verification.
- Skills do not replace reasoning, problem reformulation, tests, or runtime verification. Include concrete verification in the procedure and judge success by the result, not by whether the instructions were followed.
- Create or update a skill after observing a recurring procedural failure. Revise, merge, or remove it when it does not prevent that failure.
